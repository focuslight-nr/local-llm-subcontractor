# Claude Code への組み込み

2つのパターンがあります。トークン削減が目的なら**パターンA(下請け)推奨**です。

## パターンA: 下請けワークフロー(推奨)

Claude は頭脳・レビュー役のまま、定型作業だけローカルLLMに投げます。ポイントは
**ゲート(テスト・lint)を通ったものだけをClaudeに見せる**こと。

プロジェクトまたは親ディレクトリの `CLAUDE.md` に以下を貼り、パスを環境に合わせて調整してください:

```markdown
## ローカルLLM下請け

定型的な生成タスクは、可能ならローカルLLMに委譲してトークンを節約すること。

**委譲するタスク**(いずれも仕様が閉じていて機械検証できるもの):
- pytest等のテストコード生成
- ボイラープレート/スキャフォールド生成
- 大きなログ・ドキュメントの要約や構造化抽出(Claudeが読む前の前処理)

**委譲しないタスク**: リポジトリ横断の文脈が必要な修正、設計判断、デバッグ。

**手順**:
1. 完全な仕様を書く(入出力・エッジケース・出力形式を明記。ローカルモデルは
   曖昧な指示に弱い)。
2. `<REPO_PATH>/bin/llm -m qwen` に仕様を渡す(stdin推奨)。
3. 生成物をゲートにかける: コードなら pytest / lint、抽出なら JSONパース検証。
4. 失敗したらエラーを添えて最大2回までローカルLLMにリトライさせる。
5. ゲートを通ったものだけを自分でレビューして取り込む。
6. サーバー不達(exit code 2)や2回リトライ失敗時は、委譲を諦めて自分で書く。
```

`<REPO_PATH>` はこのリポジトリの絶対パスに置き換えてください。インストール先を
変えている場合は `LLM_HOME` も指定します(例: `LLM_HOME=~/GitHub/local-llm <REPO_PATH>/bin/llm`)。

### 削減効果の出どころ

- テスト生成1回 ≒ 出力2〜3千トークンがローカルに移る
- ログ要約: Claude が10万トークンのログを読む代わりに、ローカルで数百トークンに
  圧縮してから読む(入力側の削減が一番大きい)
- 逆に、生成物の出来が悪いとレビューで足が出ます。委譲タスクの選別が全てです

## パターンB: モデル丸ごと差し替え

Claude Code の全リクエストをローカルモデルに向けます。**API課金はゼロになりますが、
応答品質もローカルモデル相当になります**。27BクラスだとClaude Codeのエージェント
ループ(長いシステムプロンプト+ツールスキーマ)はかなり厳しいので、実験用途向け。

Ollama v0.14+ は Anthropic Messages API をネイティブに話せます:

```bash
export OLLAMA_CONTEXT_LENGTH=65536   # デフォルトの短いコンテキストでは動かない
ollama serve &
export ANTHROPIC_BASE_URL=http://localhost:11434
export ANTHROPIC_API_KEY=local
export ANTHROPIC_MODEL=qwen3.6:27b
claude
```

Bonsai(llama-server)はAnthropic APIを話さないため、丸ごと差し替えには
LiteLLM 等の変換プロキシが必要です。下請け用途(パターンA)なら不要。
