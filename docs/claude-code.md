# Claude Code への組み込み

2つのパターンがあります。トークン削減が目的なら**パターンA(下請け)推奨**です。

## パターンA: 下請けワークフロー(推奨)

Claude は頭脳・レビュー役のまま、定型作業だけローカルLLMに投げます。ポイントは
**ゲート(テスト・lint)を通ったものだけをClaudeに見せる**こと。

プロジェクトまたは親ディレクトリの `CLAUDE.md` に以下を貼り、パスを環境に合わせて調整してください:

```markdown
## ローカルLLM下請け

定型的な生成タスクは、可能ならローカルLLMに委譲してトークンを節約すること。

**委譲するタスク**(いずれも仕様が閉じていて機械検証できるもの):
- pytest等のテストコード生成
- ボイラープレート/スキャフォールド生成
- 大きなログ・ドキュメントの要約や構造化抽出(Claudeが読む前の前処理)

**委譲しないタスク**: リポジトリ横断の文脈が必要な修正、設計判断、デバッグ。
テストでも、内部APIを多く使うもの(E2E、基底テストクラスの継承、fixtureの組み合わせ)は
委譲しない。必要な定義を仕様書に収めきれないため。

**手順**:
1. 完全な仕様を書く(入出力・エッジケース・出力形式を明記。ローカルモデルは
   曖昧な指示に弱い)。
   - **ローカルLLMはリポジトリを見られない。** 書かれていない名前は推測で作るので、
     テストが触れる実際のコード(シグネチャ、データクラス定義、例外とそのモジュール
     パス、再利用するfixture、正確なimport文)を仕様書にそのまま貼る(目安300行以内)。
     import文はコメントにせずコードとして書く(コメントで渡すとコメントのまま写される)
   - 仕様書に「ここにある名前だけを使い、無ければ `# MISSING: <何が無いか>` と書く」と
     明記する。`# MISSING:` が返ったら定義を足して再送する(失敗回数に数えない)
2. `<REPO_PATH>/bin/llm -m qwen3.6:27b` に仕様を渡す(stdin推奨)。
   高速なMoE版 `-m qwen3.6:35b-a3b` は要約・抽出のような精度要求の低い一括処理向け。
   ベンチ6タスクの実測では dense 6/6 に対し MoE 3/6 で、**矛盾した仕様を申告せず
   黙って実装した**ため、コード生成の既定には向きません。
   直答では詰めきれない細かい仕様には `-m ornith-1.5:35b --think`(推論モード)。
   推論込みで約50 tok/sと速く、矛盾仕様の申告・精密パースとも実測3/3ですが、
   **テスト生成だけは期待値の算数を誤りやすい**ので既定のdense版に任せてください。
3. 生成物をゲートにかける: コードなら pytest / lint、抽出なら JSONパース検証。
4. 失敗したらエラーを添えて最大2回までローカルLLMにリトライさせる。
5. ゲートを通ったものだけを自分でレビューして取り込む。
6. 終了コードが0以外なら使える回答は無い(stdoutも空)。2=接続できない(サーバー停止、またはサンドボックスがlocalhostを遮断)、3=サーバーがエラーを返した・時間切れ(更新や再起動の最中なら再試行で直ることが多い)、4=モデルが空の回答を返した。原因はstderrに出るので確認し、対処できなければ委譲を諦めて自分で書く。2回リトライ失敗時も同様。
```

`<REPO_PATH>` はこのリポジトリの絶対パスに置き換えてください。インストール先を
変えている場合は `LLM_HOME` も指定します(例: `LLM_HOME=~/GitHub/local-llm <REPO_PATH>/bin/llm`)。

### 削減効果の出どころ

- テスト生成1回 ≒ 出力2〜3千トークンがローカルに移る
- ログ要約: Claude が10万トークンのログを読む代わりに、ローカルで数百トークンに
  圧縮してから読む(入力側の削減が一番大きい)
- 逆に、生成物の出来が悪いとレビューで足が出ます。委譲タスクの選別が全てです

## パターンB: モデル丸ごと差し替え

Claude Code の全リクエストをローカルモデルに向けます。**API課金はゼロになりますが、
応答品質もローカルモデル相当になります**。27BクラスだとClaude Codeのエージェント
ループ(長いシステムプロンプト+ツールスキーマ)はかなり厳しいので、実験用途向け。

Ollama v0.14+ は Anthropic Messages API をネイティブに話せます:

```bash
export OLLAMA_CONTEXT_LENGTH=65536   # デフォルトの短いコンテキストでは動かない
ollama serve &
export ANTHROPIC_BASE_URL=http://localhost:11434
export ANTHROPIC_API_KEY=local
export ANTHROPIC_MODEL=qwen3.6:27b
claude
```

Bonsai 2 もOllamaで動くので、同じ手順で `ANTHROPIC_MODEL=bonsai-2:27b` を指定できます。
ただし直答では精度が落ちる(ベンチ3/6)推論モード前提のモデルで、思考のぶん応答も遅いため、
丸ごと差し替えより下請け用途(パターンA、`--think` 付き)のほうが向いています。
